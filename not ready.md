## Блок 3. Введение в TypeScript

### Задача 9. Настройка простого TS-проекта

- **Задача**:
  - Создать новую папку `intro-ts`.
  - Инициализировать проект: `npm init -y`.
  - Установить TypeScript: `npm install --save-dev typescript`.
  - Создать базовый `tsconfig.json`.
- **Критерий готовности**:
  - Успешный запуск `npx tsc --version`.
  - `tsconfig.json` лежит в корне проекта.

### Задача 10. Переписать простые примеры на TypeScript

- **Задача**:
  - Создать файл `basics.ts`.
  - Переписать функции `sum`, `isAdult`, `getUserDescription` с явным указанием типов параметров и возвращаемых значений.
- **Критерий готовности**:
  - Успешная компиляция без ошибок TypeScript.
  - Понимание, зачем нужны типы (раннее нахождение ошибок).

### Задача 11. Типы для массивов и объектов

- **Задача**:
  - Создать тип `User` с полями `name`, `age`, `email`.
  - Создать массив `User[]`.
  - Написать функцию `getAdultUsers(users: User[]): User[]`, возвращающую только пользователей 18+.
- **Критерий готовности**:
  - Корректная фильтрация.
  - Понимание записи `User[]` и типа `User`.

## Блок 4. Введение в автоматизацию тестирования (Playwright)

### Задача 12. Установка Playwright-проекта (скелет)

- **Задача**:
  - В существующем или новом проекте инициализировать Playwright: `npx playwright init`.
  - Запустить пример тестов: `npx playwright test`.
- **Критерий готовности**:
  - Примеры запускаются и проходят.
  - Сотрудник видит структуру проекта (папка с тестами, конфиг).

### Задача 13. Чтение простого теста

- **Задача**:
  - Открыть один из сгенерированных Playwright-тестов.
  - Письменно описать, что делает каждый логический блок: подготовка, шаги, проверки.
- **Критерий готовности**:
  - Описание отражает реальное поведение теста.
  - Сотрудник может проговорить последовательность шагов.

### Задача 14. Написание самого простого теста

- **Задача**:
  - Создать новый файл теста `example.spec.ts`.
  - Написать тест, который:
    - открывает страницу (например, демо-сайт из документации Playwright);
    - проверяет, что заголовок страницы содержит ожидаемый текст.
- **Критерий готовности**:
  - Тест проходит стабильно.
  - Понимание, что такое `test`, `expect`, `page`.

## Блок 5. Логика тестов и работа с данными

### Задача 15. Использование функций внутри тестов

- **Задача**:
  - Вынести повторяющуюся последовательность шагов (например, логин) в отдельную функцию.
  - Использовать эту функцию в 2–3 разных тестах.
- **Критерий готовности**:
  - Повторяющийся код уменьшился.
  - Понимание, что функции помогают переиспользовать логику.

### Задача 16. Простая параметризация логики

- **Задача**:
  - Создать функцию, которая принимает разные входные данные (например, логин/пароль) и возвращает результат (успех/ошибка).
  - В тестах вызвать эту функцию с разными аргументами.
- **Критерий готовности**:
  - Логика работает для разных наборов данных.
  - Видна связь между параметрами функции и поведением теста.

## Блок 6. Закрепление и мини-проект

### Задача 17. Мини-проект «Тесты для простой страницы»

- **Задача**:
  - Выбрать простой публичный сайт либо внутреннюю тестовую страницу.
  - Описать 3–5 тест-кейсов вручную.
  - Реализовать эти тест-кейсы в Playwright с использованием:
    - функций;
    - типов (в TypeScript, если проект на TS);
    - базовых структур данных (массивы, объекты).
- **Критерий готовности**:
  - Все тесты запускаются и проходят.
  - Сотрудник может объяснить структуру мини-проекта и расположение файлов.

### Задача 18. Код-ревью с ментором

- **Задача**:
  - Создать MR/PR с мини-проектом.
  - Пройтись по комментариям, исправить замечания.
- **Критерий готовности**:
  - Все базовые замечания (переменные, функции, типы, структура) устранены.
  - Сотрудник понимает основные ошибки и может их озвучить.
